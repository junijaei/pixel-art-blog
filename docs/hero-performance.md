# Hero WebGL 최적화

기존 입자·궤도·다면체 장면을 직접 WebGL로 구현했다. React Bits의 GPU 일괄 렌더링과 가시성 기반 실행 원리를 참고했으며, 해당 컴포넌트의 소스나 디자인을 복사하지 않았다. 추가 의존성은 없다.

## 변경 구조

- `hero-webgl.ts`: 고정 GPU 버퍼와 시간·테마 uniform으로 장면을 렌더링한다. 히어로에서 Three.js, React Three Fiber, Drei를 가져오지 않는다.
- `hero-geometry.ts`: 고정 시드 입자, 다면체의 평면 법선, 와이어프레임과 궤도 데이터를 만든다.
- `hero-scene.tsx`: WebGL 생성·해제·컨텍스트 복구, 크기와 가시성 관찰을 담당한다.
- `hero-animation.ts`: 최대 30fps로 그리며 화면 밖·숨겨진 탭에서 정지한다. 동작 축소 설정에서는 필요한 경우에만 한 번 그린다.
- `hero-motion.ts`: 시스템 동작 축소 설정 변경을 구독하며 서버와 클라이언트의 첫 렌더 결과를 일치시킨다.
- `hero-cosmos.tsx`: 작은 네이티브 렌더러를 직접 가져와, 마운트 후 추가 3D 청크를 기다리는 경로를 제거한다.

Canvas는 배경과 중앙 도형 두 개를 유지한다. 배경 → HTML 텍스트 → 중앙 도형 순서를 보존하기 위한 선택이다. 중앙 Canvas는 전체 화면 대신 히어로 높이의 40%인 정사각형으로 잘라서, 전체 높이를 이용한 투영으로 도형 크기를 유지한다. 배경 DPR은 1, 중앙 도형 DPR은 최대 1.5다. 얇은 궤도 품질을 위해 안티앨리어싱은 유지한다.

## 측정 결과

변경 전 로컬 프로덕션 빌드와 변경 후 `pnpm build` / `pnpm start --port 3100`을 Chromium의 새 브라우저 컨텍스트에서 비교했다. 네트워크가 안정된 시점의 script 리소스 `encodedBodySize` 합계이며, 실제 사용자 통계나 배포 CDN 측정값은 아니다.

| 항목                 |       변경 전 |       변경 후 |
| -------------------- | ------------: | ------------: |
| 홈에서 받은 JS       | 498,710 bytes | 251,420 bytes |
| JS 감소율            |             — |         49.6% |
| 데스크톱 배경 Canvas |    1392 × 835 |    1392 × 835 |
| 데스크톱 중앙 Canvas |    1392 × 835 |     334 × 334 |

변경 후 모바일 390 × 844, DPR 2에서는 배경 390 × 784, 중앙 471 × 471 픽셀이다. 프로덕션 클라이언트 청크에 Three.js의 `WebGLRenderer`가 없음을 확인했다. 이 수치는 다운로드량 감소를 입증하며, LCP가 같은 비율로 개선된다는 의미는 아니다.

## 검증

- 전체 테스트: 37개 파일, 289개 테스트 통과. 히어로 전용 테스트 12개 포함.
- 프로덕션 빌드 및 빌드 내 TypeScript 검사 통과. 홈 정적 생성 유지.
- ESLint: 오류 0개. 기존 `features/post/query/post.ts`의 `_updatedAt` 미사용 경고 1개.
- 변경 파일 Prettier 검사, `git diff --check` 통과.
- 데스크톱·모바일 × 라이트·다크: 셰이더 링크, GL 오류, 가로 넘침, 동작 축소 시 정지, 설정 변경 후 재개, 화면 밖 정지 및 복귀, WebGL 컨텍스트 복구 확인.
- WebGL을 사용할 수 없어도 제목과 글 목록 링크가 표시됨을 확인.
- 화면과 측정 자료: `.omx/hero-performance/`.

## 남은 차이와 범위

전용 셰이더로 재구현했으므로 반사광·글로우·입자 분포는 기존과 조금 다르다. 중앙 도형이 텍스트 앞에 놓이는 기존 구성은 좁은 화면에서도 유지했다. WebGL 미지원 환경에는 정적인 3D 대체 이미지가 없으며, HTML 콘텐츠는 정상 표시된다.

빌드 환경에 `CLOUDFLARE_API_KEY`가 없어 기존 이미지 처리 코드가 Notion URL로 대체하는 경고가 발생했다. 히어로와 무관한 CDN 설정은 변경하지 않았다. 의존성 선언은 유지했지만 히어로에서는 Three 계열을 로딩하지 않는다. 배포는 수행하지 않았다.
